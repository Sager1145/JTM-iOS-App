## Architecture judgments (separate from defects)

- **TimetableQuickMatchController has useful depth and locality.** Its small `updateInput/search/cancel` interface owns request identity, debounce, result staging and suppression of canceled publication ([TimetableQuickMatchController.swift:58–126](/Users/sager/Documents/GitHub/JTM-iOS-App/ios/RailMap/Timetable/TimetableQuickMatchController.swift:58)). The injected Lookup/Debounce closures provide an internal test seam for suspended requests. The production adapter is `TimetableQuickMatchLookup` (132–152). Preserve this ownership when adding lifecycle regressions; views need not reconstruct request IDs.
- **StationPickerSearchController similarly hides meaningful implementation behind a small interface.** Its load token and request token serve different lifetimes ([StationPickerSearchController.swift:57–108](/Users/sager/Documents/GitHub/JTM-iOS-App/ios/RailMap/JourneyEditor/StationPickerSearchController.swift:57)), so prepared-load installation and debounced filtering can be tested through the same interface that the view uses. Region/line/date/retirement identity is explicitly represented. This is a useful existing seam, not a reason to add an unrelated abstraction.
- **RailNetworkStore earns substantial leverage, but contains several independent owners.** `ensure(region)` exposes canonical editor needs while `ensure(regionsIntersecting:cameraZoom:)` exposes display residency; each hides package decoding, index work and caching. The loader's dependency closure, overview/full replacement, eviction and deterministic publication are centrally owned ([RailNetworkStore.swift:805–1103](/Users/sager/Documents/GitHub/JTM-iOS-App/ios/RailMap/Infrastructure/Network/RailNetworkStore.swift:805)). Canonical WGS84 cache seeding remains separate from Apple Map display transformation (1595–1610). The serialized reset/interface has distinct manifest, display batch, indexing and canonical decode lifetimes: manifest uses a load epoch (471–496), display batches suppress canceled publication (983–990), while canonical `decodeGeometry` publishes from an untracked task (656–708). I did not establish a reachable user race for that last difference because the current retry button is only exposed after pending decodes finish; treat it as an interface invariant to clarify if reset callers expand, not an actionable concurrency defect yet.
- **ServicePatternPickerView concentrates search semantics, daily DB loads and UI composition.** `SearchInput/SearchSnapshot` (124–140,91–111) are useful value seams, and the view guards date/filter/generation before allowing selection (174–175,618–692). However the view and search implementation share many state fields; a future behavior change can improve locality by extracting the complete search/load owner behind one narrow interface, following the existing QuickMatch/StationPicker owners. This is an architecture opportunity, not a mandate to split merely because the file is 694 lines.
- **MapInteractionCoordinator is a focused module with a concrete interface.** It owns the ride tap index and claim shared by two MapKit tap paths ([MapInteractionCoordinator.swift:18–50](/Users/sager/Documents/GitHub/JTM-iOS-App/ios/RailMap/Map/MapInteractionCoordinator.swift:18)), receives drawn geometry instead of becoming a selection owner, and resets its private caches in one place (71–77). MapPlaybackLayer likewise owns mounted playback overlays/annotations and per-step trail state behind render/repaint/clear, allowing the parent coordinator to avoid duplicating overlay cleanup. Neither observation establishes measured frame time, leak behavior or bitmap correctness.
