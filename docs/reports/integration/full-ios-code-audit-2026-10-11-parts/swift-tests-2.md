### T6 — P2: The map-probe assertions accept missing measurement evidence as a pass

Location: [ios/RailMapUITests/MapIndependentRailPrototypeUITests.swift:126–131](/Users/sager/Documents/GitHub/JTM-iOS-App/ios/RailMapUITests/MapIndependentRailPrototypeUITests.swift:126); consumers at 24, 27, 31, 33–37 and 71, 74, 76–79. Supporting production metric contract: [ios/RailMap/Diagnostics/MapIndependentRailPrototype.swift:560–595](/Users/sager/Documents/GitHub/JTM-iOS-App/ios/RailMap/Diagnostics/MapIndependentRailPrototype.swift:560).

`value` returns `-1` for an absent field or failed numeric parse. The error and latency assertions impose only an upper bound, so `-1 <= 1`, `-1 <= 8`, `-1 <= 16`, and `-1 <= 150` all succeed. The producer itself deliberately emits `-1` for empty percentile inputs at 576–579. Thus this is also an existing no-samples sentinel, not merely a hypothetical future schema change.

Concrete missed failure: the diagnostic rail's draw callback fails to run while the camera/update/reference sampling continues. `paintCosts` and `pairedCosts` are filled only by `draw` (570–571). Both can remain empty and publish `-1`; the test accepts those values, never requires `drawnFrames > 0`, and attached screenshots have no raster assertion. The independent reference/sample/motion counters do not establish that the rail's paint callback executed. Similarly, deleting or damaging an emitted error/latency field can leave all of its upper-bound assertions green.

Recommendation: require every asserted metric to be present, numeric, finite and nonnegative before applying its ceiling. Require the existing draw/sample counters appropriate to each reported percentile. Keep the opt-in diagnostic scope; this finding does not establish a production paint failure or justify a broad probe campaign.

### T7 — P2: The share ratio matrix can pass while every requested ratio is ignored

Location: [ios/RailMapUITests/ShareComposerMatrixTests.swift:25–32](/Users/sager/Documents/GitHub/JTM-iOS-App/ios/RailMapUITests/ShareComposerMatrixTests.swift:25), `212–256`, `306–325`. Supporting producer: [ios/RailMap/Sharing/ShareComposerModel.swift:5–60](/Users/sager/Documents/GitHub/JTM-iOS-App/ios/RailMap/Sharing/ShareComposerModel.swift:5); debug value at [ios/RailMap/Sharing/ShareComposerView.swift:803–824](/Users/sager/Documents/GitHub/JTM-iOS-App/ios/RailMap/Sharing/ShareComposerView.swift:803).

The preset/ratio matrix creates five ratio cases per preset but never asserts that the effective ratio equals `item.ratio`, nor compares the PNG aspect to an independent expected ratio. `assertExport` only compares PNG width/height to the app's `px` debug field; both are derived from the same production size calculation. The literal 2160 long-edge oracle is supplied only by `testLargePresetExportsUse2160PixelLongEdge`, whose cases retain the default portrait ratio.

Concrete missed failure: debug ratio configuration stops being parsed/applied and every launch uses the default portrait ratio. Every matrix case still reaches ready, reports its actual default dimensions, exports a PNG of those dimensions, has the expected light/dark scheme and can report no overflow. The matrix then succeeds without exercising square, landscape, wide or tall output. A broken shared aspect mapping can likewise make its debug dimensions and exported dimensions agree.

Recommendation: assert the effective ratio against the requested case, and assert exported width/height or aspect against the explicit ratio specification (1:1, 4:3, 3:4, 16:9, 9:16) with the documented pixel-rounding tolerance. Preserve the current real-PNG checks. This is a test coverage defect; the currently inspected production ratio mapping is correct.

## Test-surface judgments and limits

- Core geometry/routing regressions mostly use fixed expected identities, literal surveyed points, half-open opening/retirement boundaries, explicit negative cases, or saved JavaScript answers. Counts are commonly asserted before zipped element comparisons. Relationships such as reverse travel and source/display preservation have appropriately narrower meaning than independent geographical certification.
- ContinuousStrokeParityTests combines saved JavaScript output with separate finite/monotone, turn-angle and radius properties. The bend-preservation suite has hand-authored survey/hairpin fixtures and self-intersection checks. Some low-level helpers are intentionally tested directly; this is not an instruction to expose more internals or add another suite.
- ImportParityTests tests the production synchronous Session interface and its event/state contract. Its `parts` helper reconstructs request/retry/prefetch orchestration around production helpers, and `manifests` skips actual fetch-failure work because transport is outside that pure interface. These methods prove helper parity, not native asynchronous fetch/retry lifetime. Per-case log/session state is local; no new shared-state race was found there.
- JourneyCompletionTests uses real public merge/prompt/catalog interfaces, exact errors in many rejection paths and substantial literal chronology/identity examples. The atomicity assertions on unchanged input value structs are narrow; the thrown whole-batch result is the substantive failure contract. It does not prove the native request cancellation or editor save lifetime.
- JunctionApproachTests and OnEdgeCertificationTests use PhysicalEndpointTrimTests helpers to reconstruct source-first / graph-fallback route processing. The large census prints baseline/expanded totals but does not assert a global improvement or that all sample routes have zero gaps; only the specific Oki result and applicable matching reviewed boundaries are enforced. Treat the output as diagnostic census evidence, not all-route acceptance. This duplicates some production orchestration and cannot establish the native decoder/publication path. The tests do not turn display through-service relationships into physical graph proof.
- RouteStoreStressTests has real synchronous import/export/collision/rollback/value-copy assertions. Timings are printed, not bounded performance verdicts. Optional environment-supplied stores/parts are fail-fast data alternatives rather than silent missing-fixture passes. No heavy job was run.
- Pattern persistence tests exercise Codable and canonical import/export, then cold route-section regeneration. Their endpoint snapshots/template key prove the captured identities and shape, not native disk-write ordering or arbitrary per-leg physical metadata. Those durability concerns belong to native storage tests and the known UI persistence findings in the parent's production audit.
- UI launch storage IDs are UUID-scoped in the assigned normal flows, and waits are bounded. Several UI tests use fixed settling sleeps; static review cannot establish their reliability or timing under load. Capture-only helpers and ConsoleSweepTests are explicitly diagnostic drivers, not pixel or console-cleanliness verdicts. The console driver intentionally accepts a legitimate empty journey list.
- Map camera/layer UI tests observe mounted debug status, concrete selection states, coordinate changes, endpoint-card bounds and (for density) the ADR's literal formula. These are valuable renderer integration observations but not a substitute for actual rail raster/geographical correctness. Missing overlay-count fields can also satisfy string-negative `!contains(overlays:0)` checks; numeric unwrapping is a stronger existing pattern elsewhere in MapLayerToggleTests.
- Share matrix writes use a shared export directory and stable case names, but a stale-file false pass was not established: `debugReady` requires `renderer.debugExportedKey == renderKey`, so an old PNG alone cannot satisfy current readiness. The matrix covers automatic debug exports; ConsoleSweepTests separately drives the user Export action. PNG dimensions and attachments do not establish all card text/rail pixels are correct, and comparisons to the statistics page share its data source.
- The prototype gate still names a retired standalone runner. This is a stale explanatory string, not authorization to recreate it. Raster probes deliberately capture phase evidence without asserting screenshot pixels.
