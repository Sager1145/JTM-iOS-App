## 区域方向证据

本次只把官方区域资料用于线路身份和大方向，不把它当作站内几何测量：

- 名古屋铁道官方须ヶ口路线页列出名古屋本线的名铁一宫/名铁岐阜方向、名铁名古屋/金山方向，以及津岛线的津岛/弥富方向：<https://trainbus.meitetsu.co.jp/meitetsu-transfer/pc/diagram/TrainRailRoadSearch?nodeId=00004518>。
- 名古屋铁道官方津岛线页面以须ヶ口为线路东端并注明接续名古屋本线：<https://www.meitetsu.co.jp/train/station_info/line10/index.html>。
- 名古屋铁道官方名古屋本线页面在须ヶ口注明津岛线接续：<https://www.meitetsu.co.jp/train/station_info/line01/index.html>。
- 国土地理院地理院地图定位：<https://maps.gsi.go.jp/#18/35.198930/136.845755/&base=seamlessphoto&ls=seamlessphoto&disp=1>。独立查看了官方 `seamlessphoto` z18 图块 `x=230719..230720, y=103656..103658`，临时拼接图仅用于本次审查。

国土地理院俯瞰资料支持以下区域级结论：

1. 须ヶ口站场和可见站台组总体沿西北—东南方向排列。
2. 名古屋本线保持西北—东南主走向；津岛方向轨道在站场西北侧沿共享走廊后向西分出。该方向与源数据中 Main #17 尾部和津岛 #0 头部的三点反向共享一致。
3. 从名古屋方向进入津岛线的可通行序列仍是 Main #18 反向（新川橋→须ヶ口）接津岛 #0 正向（须ヶ口→甚目寺），不是在须ヶ口回头，也没有证据支持绕行 U 形支线。

航空影像的日期、分辨率和线路使用信息不足以判定某一股站台面专属于津岛线或名古屋本线，因此不从该资料提取站内坐标。

## Apple z18 站台组判读边界

Apple z18 原图为 999×654，源站点 `[136.845755,35.19893]` 投影在 `(499.5,327.0)`。宽蓝框内部不是单一站台矩形，而是多组沿西北—东南方向、长度与端点不同的平行蓝色带和黑色轨道：

- 西北侧可见一组较短的蓝色站台/轨道面，约从 `(440s,270s)` 延伸到 `(570s,350s)`；现有点落在这组短面纵向中部附近。
- 另有更长的蓝色带继续向东南延伸至约 `x=700s` 以后；把这些不同面和站房填充合并为一个“大框”再取中心，会把点推向没有线路身份依据的位置。
- 黑色自身轨道、站名文字、蓝色填充和多股平行线在 `(450..600,280..380)` 区域重叠。现有原图不能唯一证明短面、长面中的哪一面应承载共享的 Main/Tsushima 站点圆点，也不能可靠读出该面的两个纵向端点。

因此当前判读是：

- 可以确认所有候选自身面都沿西北—东南方向，不应产生横穿站台的折线。
- 可以确认津岛 #0 在站外西北弯段整体偏到自身黑色双轨南侧，需要完整区间拟合。
- 不能确认须ヶ口显示站点坐标应离开 `(499.5,327.0)`；现点可能接近其中一组自身短面的纵向中点。若后续更清晰的原图能把共享进路对应到唯一站台面，才可从该面的纵向两端取中点并向自身黑轨作法向投影。
- 不得把整块蓝色站房/站区轮廓、线路文字、道路或相邻长面端点当作坐标依据。

## Main 五区间检查要求

`main-camera-plan.json` 给出仅用于 Main 完整区间配对的计划相机。原有 #17/#18 数值未改，新增 #16、#19、#20。实际采集时每一项都必须满足：

每个 `plannedCamera` 依照现有完整区间计划格式写为 `[中心纬度, 中心经度, spanDelta]`：中心取该区间源坐标包围盒中心，`spanDelta` 取经纬跨度较大者的 1.5 倍。这只是可复算的起始画幅；运行时仍须确认全部实际显示点在画面内。

1. ON 与 OFF 使用相同实际相机，并完整容纳该区间的全部源/显示点。
2. #16 要显示新清洲端、完整进路和丸ノ内站框；丸ノ内显示 alias 若移动，#16 尾与 #17 头必须使用同一精确坐标并形成自然切线。
3. #17 要显示丸ノ内端、完整西北进路、与津岛 #0 反向共享的最后三点以及须ヶ口圆点。
4. #18 要显示须ヶ口圆点、向新川橋方向的完整东南进路和新川橋端点。
5. #19 必须从修正后的新川橋同一点自然进入东西向自身轨道，并在二ツ杁修正后的自身站框中点结束；#20 必须从该同一点续接到西枇杷島。
6. 五项必须一起检查共享 `005352` 是否为同一像素、#17/#18 是否自然贯通、#17 与津岛 #0 是否在真实共享干上逐点重合后于实际分岔分开，以及 #18/#19、#19/#20 的端点是否逐点相等且无回接折钩。
7. 数值 bounds、无裁剪计数或 AX 文本只能证明画幅覆盖，不能代替像素贴轨和站台面身份审查。

Third `002452/000000` 的丸ノ内原图显示物理点 `(512,384)` 位于自身 NW-SE 蓝色站框的东南端附近，而非纵向中点，因此 #16 是已证实的 guard 扩展。Third `002453/000003` 对新川橋显示同类问题。后续三幅 z18 原图把范围进一步定实：丸ノ内自身窄站框纵向中点法向投影约为原图 `(474,231)`；新川橋约为 `(454,269)`；二ツ杁约为 `(482,309)`。三者分别要求 #16/#17、#18/#19、#19/#20 使用同一精确 alias。像素到坐标的换算仍属于候选证据，不在本文批准生产值。

新清洲 z18 具有多股轨道和多组蓝色站台面，无法唯一辨认应承载 `005323` 的自身面；因此保留现 guard 并标记 WARNING，不向前扩到 #15。西枇杷島 z18 中物理点接近自身东西向窄站框纵向中部，法向距离约 2.5 m；它作为 #20 外侧 guard 保留，不扩到 #21。两项都不构成对站内测绘精度的证明。
