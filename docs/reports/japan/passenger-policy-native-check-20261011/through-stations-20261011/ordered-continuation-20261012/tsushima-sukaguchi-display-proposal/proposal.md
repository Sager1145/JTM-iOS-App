## 目的和边界

本目录把津岛线 #0 七幅 z18 原图中可辨认的自身黑色轨道中心整理为重投影支持线，并记录名古屋本线相邻站框的纵向中点候选。它不是可直接写入 `jp-2025.json` 的完整 owner candidate：须ヶ口多站台组仍不能唯一证明承载共享 `005352` 圆点的具体站台面，故没有把旧 alias 到第一条可见黑轨之间的虚线当作轨道，也没有生成 `displayBranchLeadIns`。

物理站 ID、公里、线路方向、实际 switch 和源拓扑均未改。生产源、builder、evidence gate 和父账本均未写入。

## 共享干约束

Main #17 与津岛 #0 的源数据在须ヶ口一侧有至少三点精确反向共享。最终 owner candidate 必须继续满足：

1. 两条线路对共享干使用逐点完全相同、方向相反的显示坐标。
2. 分离只能发生在 Apple 原图可见的真实 switch 位置；不得在站框中心制造回头或横穿站台。
3. 须ヶ口圆点必须是被证实的自身站台面纵向中点；目前证据不足，所以本草案只保留 unresolved marker。
4. 如果共享干变化，必须提交完整 Main #17 和完整津岛 #0 数组；不得只补局部 lead-in 或依靠旧 source guard 回接。
