## 可直接写入构建规范的规则

**O：线路、珠、站名、线名分别变化。** 03 的无名珠、04 的普通站名退出和保留路径是直接例证。不能用同一个布尔值开关四层，也不能把无名珠变成无站 junction。近景设施符号是另一种表示，不是无限放大的普通圆点。

**R：先让整条已纳入走廊保持可追踪，再独立筛站位与名字。** 站名字体维持可读大小，以数量和空间碰撞降低密度。允许普通珠留下而文字退出；文字胜出的站需要一个可辨的站位符号。被选中站的优先显示单独处理，不能用搜索高亮来衡量普通站大小或默认标签门槛。

**O：线名并不随站名一起增加。** 02 有多段沿路径文字，03 相同地区的沿线字减少，同时仍有许多站名。**R：** 线名由当前可用弧长、曲率、重复间距与占位决定，不能只设置为“zoom 越大出现得越多”。站名字形保持屏幕可读方向，线名顺切线。

**O：浅色不是把所有颜色反转。** 浅色地图上 JR 绿色更深，站名为深灰并带浅色分隔，线名仍按铁路着色；细线和珠周围可见浅色隔离。深色为明亮站名和低亮背景。东海道新干线的蓝色条带在浅色画面中出现浅色内部段，在深色画面中出现暗段；这不证明每条带状铁路的语义。

**R：** 主题分别指定线路色、文字、halo/casing、站珠边缘和条带内部色；完整墨迹包络用于计算并行间距。条带内段依最终路径弧长连续排布；更换主题只改绘制，不改变路径/身份。运营状态 dash 与类别纹理仍分开。上述截图没有测出精确 RGB、pt 线宽或文字字体，不把设备像素直接当 iOS point。

**O：主题切换后个别文字会变化。** 05 浅色出现与深色不同的沿线名称位置。**R：** 几何、尺度和身份可以固定，标签碰撞/排序的结果可能不同；不要要求深浅主题逐字逐位置一致，也不要把标签变化解释成轨道变动。

## 富山 junction：补上上一轮未查看的近景

本轮独立打开已有 `ujina-complete/apple-maps-transit-style/marunouchi-junction-detail.png`（相对于 `docs/reports/japan/passenger-policy-native-check-20261011/through-stations-20261011/ordered-continuation-20261012/`）。原图 1512×871，比例尺 12 m。选中的是西侧公园卡；丸之内站及北向/东西向绿色墨迹未被大蓝色选站图标遮住。

**O：** 北臂在站名与 2/3/5/6 徽章附近汇到一点，向西南和东南各画一条明显斜线，然后向东西街道展开；画面没有另画一条穿过三角底部的东西直行线。局部是简化的角状表示，不能用先前被站点图标遮住的 overview 推断所有转向。徽章仍不等于四条独立轨道。

**R：** 原生 cartography 可以压缩真实路口形态；用该例说明“不同城市的示意程度不同”。JTM 若要保留实际铁路几何，应依据自己的客运连接对和区域证据保留实际平顺进路，不能把富山的角形复制成物理 cusp。广岛纸屋町的东西主干加两条南向弧，是另一种可见结构。两者都不授权从三臂自动补全所有物理连接。

原生图只证明可见画法；Ujina 候选仍是另一任务中的局部 proposal，未因本指南而应用或验收。
