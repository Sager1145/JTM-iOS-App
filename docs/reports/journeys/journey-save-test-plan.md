# 添加行程与保存：自动化测试计划

范围：原生 iOS 添加向导、已有行程编辑、共享数据规则、保存队列与磁盘恢复。以当前工作区分步提交后的版本作为基线；保留已有实现，不将基线提交视为测试通过。

## 分工与覆盖

| 层次 | 负责人 | 自动化覆盖 |
| --- | --- | --- |
| 用户界面 | editor_ui subagent | 五步向导、必填校验、前后切换保留草稿、车站匹配、线路选择、服务及车辆字段、日期、站点增删/撤销、地区切换、取消、编辑保存、旋转、中文与大字体 |
| 数据规则 | core_rules subagent | 新增、重复 ID、复制、替换、顺序、日期、可选元数据、JSON 导出/验证/重新导入；运行 RailKit 全套测试 |
| 保存与恢复 | persistence subagent | 连续保存、队列顺序、写入错误与恢复、备份、地区分区、拒绝修改、生产保存实现的隔离自动化测试 |
| 集成 | 主 agent | 补充编辑校验覆盖、核对界面与保存边界、审查修复、运行相关回归、记录实际通过/失败/未覆盖范围 |

## 执行步骤

1. 按功能提交现有改动，建立可回退基线。
2. 检查已有测试与功能清单，补齐有实际断言的缺口。
3. 独立运行纯逻辑、存储及模拟器 UI 自动化，保存日志和测试结果。
4. 对可复现问题补回归用例并作最小修复；按问题分步提交。
5. 重新运行受影响测试及必要的集成测试，汇总数量、命令、缺陷和限制。

## 验收标准

- 无效输入不能进入保存成功流程，有效输入新增/编辑后内容一致。
- 保存队列最终写入最新数据，失败不会被报告为成功或覆盖可恢复数据。
- 元数据、地区与记录身份经保存/重新加载后保持正确。
- UI 测试使用隔离模拟器数据；存储测试不写入用户实际行程库。
- 未执行或受环境阻塞的用例明确列出，不能计为通过。

实际结果另记于测试报告。
