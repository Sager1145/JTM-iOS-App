## 相同输入与可比范围

每个车次运行两种模式：

1. `endpoint-only`：只给真实始发、终到站，各引擎求解一次。
2. `forced-known-stops`：给相同的实际停站顺序，逐个相邻停站求解。原仓库本身没有此贯通 API，此模式由其未修改的原始路径 API 逐段调用组成。

每个引擎共 176 个车次/模式组合、1,098 个请求区段。未添加目标里程、指定线路 ID、直线补桥或人工推荐路径。原生输入保留车次号与公开列车类别，公司为空，地区限定 CN；独立审阅确认这些输入没有缩窄机构范围。

原仓库固定于 [d75307d](https://github.com/Laide140/CRTrainRoute/tree/d75307df9c812abf1259b86b75202ba7b0048679)，运行其原始 RailService、图、吸附及最短路径逻辑。在线站点坐标接口一次探测返回 HTTP 502，因此使用同一提交的站点 JSON 原值作离线坐标传输；不使用 Railmap 坐标修补。该限制影响结果，不能把所有失败归因于原算法。[详细基线方法](baseline-method.md)、[采集记录](baseline-acquisition.json)、[在线探测](baseline-live-probe.json)。

Railmap 使用正式 CN 数据、生产原生求解器及其实际 WGS84 `sourceCoordinates` 导出（旧图求解段沿用既有坐标量化）。正式统计来自隔离 Release 应用的完整 176 项结果，完成时间 2026-10-18T22:11:30Z，状态为 `active=false / completed / evidenceReady`。CN 修订为 `b649bfad5dbccf4f2d36abee345c03cef91988a46988d8d200c32c5c3e40ab6e`，包含哈尔滨连接修复。中断的 Debug 与两个 Release 检查点不混入最终统计。[实际执行环境](native-execution-context.json)保留了程序副本、签名与输入核对范围。这里不作耗时或内存优越性比较。

## 指标的含义

“完整返回”要求全部请求区段有确定索引覆盖，且无未解析区段、无物理断点。它只说明求解器可返回完整候选路径，不等于真实列车经由已经验证。

“返回几何区段”按确定的 sectionIndex 去重，多部件折线不重复计数；未知索引保留未归属数量。原生内部“已解析数”还会排除物理断点涉及的区段，因此不是原仓库 API ok 段数的直接等价物。报告同时列出几何返回、内部计数和断点条目；原仓库没有等价断点模型，不将缺失字段当作已证明为零。

只对完整候选做停站几何筛查：将官方停站映射到 CN 原始 OSM 站点标记，计算点到候选折线的距离，超过 2 km 标记复查。未知或歧义站点保留未参考数量；未执行筛查在 CSV 中为空，不能当作零偏离。这些 OSM 参考点与 Railmap 建站资料同源，特别是强制停站模式不能算独立外部精度验证。该阈值不是站轨归属或拓扑连接规则；不同折线段之间不补虚构线段。两方长度均用相同球半径重算；不比较残缺路径的总长优劣。

原仓库的原始渡轮猜测、警告、吸附偏移与坐标基准差异保留。中国大陆及香港高铁只使用 CN；香港其余铁路属于 HK、澳门轻轨（含横琴）属于 MO，互不交叉连接。

## 原始基线的已完成观察

本节的 Railmap 数字为首轮结果；原始基线未改变，当前原生结果见文末。

88 个车次中，原仓库起终点模式返回 75 个，13 个首个报错均是离线快照缺坐标。停站约束模式返回 756/1,010 段；121 段首先报缺坐标，133 段首先报站名解析问题，未观察到算法报错。前置站点错误可能遮蔽后续连通性问题，不能据此证明图上都能到达。

G203 为南京南→贵阳北，官方停站先经过无锡东、苏州北、上海虹桥再向西南。原仓库起终点候选 1,553.572 km，停站约束候选 2,099.559 km；Railmap 起终点候选 2,074.721 km、约束候选 2,073.771 km，11 个可参考停站均在阈值内。长度由同一公式重算，不能因为更短或更接近另一候选就认定实际轨道正确；此例只证明候选对已知停站的符合差异。

G383 起终点候选长度 1,572.108 km，距离官方实际停站长沙南约 485.222 km；按全部停站逐段调用后候选长度 1,956.256 km，11 个有 OSM 参考点的停站均通过 2 km 几何筛查。G237 起终点候选距离贵阳东约 327.819 km；约束后九个可参考停站均通过，成都东没有参考点。这里只能证明原始起终点最短路与已公布停站不符，不能由此认定约束后的每条轨道均是真实经由。

G255 即使加入停站仍有泉州东异常：官方顺序为莆田→泉州东 QRS→厦门北，原始快照 QRS 为 `[118.639202,24.920462]`（丰泽区城东街道），两段吸附偏移仅 322.1 m、无警告；当前福厦高铁 OSM 标记 7137144036 为 `[118.7658438,24.9247217]`。站点原值相距 12.779 km，候选折线到当前标记为 12.979 km。政府资料区分[城华南路旁的原火车东站](https://zyghj.quanzhou.gov.cn/xwdt/gzdt/202512/t20251218_3243224.htm)和[台商投资区东园镇的新高铁站](https://www.quanzhou.gov.cn/zfb/xxgk/zfxxgkzl/qzdt/qzyw/202012/t20201224_2485913.htm)。旧址/新址同名可解释该快照差异，但历史坐标位置的对应仍是推断；这个问题不能算作最短路径算法失败。

D69 的另一个强制停站异常是吐鲁番北 TAR：原始快照与 OSM 站点相距约 319 m，但相邻两段均吸附到 14.351 km 外的铁路网，并明确返回远距警告；候选距当前站点标记 13.290 km。这是原图吸附／覆盖问题的直接证据，不能归为已证实的同名旧新站问题。原仓库此车返回 14/14 段，Railmap 仅返回 3/14 段，不比较残缺整车总长。

地方列车 5633 仅 3/25 个停站有可用参考点，即使零项超阈值也不能视为完整停站验证。Z385/Z386/Z501/Z502/K457/K458 六个起终点返回保留原仓库渡轮注记，其 21.06 km 猜测线不能作为独立物理连接证据。

## 完整批次暴露的元数据与站轨归属缺陷

原始完整 176 项诊断保留 71 项 `malformed_selection`：6245、6246、5619、5620 的强制停站模式分别 20、19、16、16 项。名称输入的小站已经由求解器选中原始 CN-OSM 站点，后续几何匹配记录却丢失端点 ID。修复只在绘制完成后，从实际所选站点补齐选择元数据；无身份仍返回未证明，不捏造官方站码。旧缓存仅在已有结构检查不合格时重解，未全局清空或改缓存世代。修复与整批重放已完成，结果见文末；原始 71 项失败不抹除。

只读复核另发现两段明确误用地铁：D271 强制停站第 10 段（零基）与 C293 第 0 段，均为官方昆明 KMM→昆明南 KOM，却返回昆明地铁 1 号线 `cn-osm-relation-7909742` 的 294 点／293 条边，24.870442 km，源几何逐边吻合。源关系 7909742 v17 及 11 条 ways 均明确为 subway；地铁站点没有被 Builder 赋予国铁官方站码，站轨身份在数据中仍分离。问题在运行时允许站点吸附到 500 m 内其他轨道。两车整车本来就是残缺，因此 12 条完整候选数量不受影响；480 个已解析请求区段中也不能把这两段算作正确国铁路段。原始轨道锚点归属修复与完整重放已完成；两段现在保留为未解析，不能把删除错路说成已补通国铁。
