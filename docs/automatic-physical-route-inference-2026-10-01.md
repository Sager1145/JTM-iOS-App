# 根据输入车站识别具体线路走向

本方案用于新增和编辑行程。目标是让系统利用用户已经填写的车站、车次和线路约束，尽量自动提出具体物理路径；无法区分的部分只需补充一条有效线索或选择一次地图走法。东京局部默认规则已实现；下文通用搜索仍为后续方案。新桥和赤羽桥的绘制修复另行验证。

根据用户明确要求，东京、新桥、品川局部区间未记录有乐町或其他地面专属站时，默认选总武／横须贺地下物理区间。这是应用偏好，不表示数学上只有一条可能路径。人工选定的地面线路、明确区间编号及地面站点优先。

## 当前实现与缺口

`RailwayRouteChoices.choices` 已能返回单条线路及同运营者同名线路分段的候选。候选保存有序 `sectionCodes`，能够区分站序相同但轨道不同的走法。`RailwayRouteEditing` 已支持局部替换、重复经过站的 `visitID`、人工站点保护和撤销。明确区间编号可以进入存储、特急数据库及 AI 提示。

当前查询输入只有起终点、车型和明确排除站点，还没有把全部人工填写的中间站作为联合约束。也没有通用的跨异名线路物理连接关系，不能因为共用站码就新增同车直通边。全程线路偏好和相邻区间分别求最短路都不能替代具体走向识别。

## 证据如何参与判断

| 输入 | 用途 | 边界 |
| --- | --- | --- |
| 人工输入的车站及顺序 | 候选必须依次经过相应站点出现实例 | 不合并重复经过的同一站 |
| 已明确选择的物理区间和方向 | 固定该范围，不允许自动改写 | 线路名不足以锁定所有同名轨道 |
| 可核验的车次、乘车日期和物理区间关联 | 匹配具体服务的路径；矛盾时报告冲突 | 仅有服务名称或缺乏径路关联时不能作为物理轨道证明 |
| 站台、地下或地面等明确线索 | 约束站台成员和对应路径 | 复合车站中心点不能替代站台成员 |
| 运营者、距离、换线次数和全程偏好 | 排序候选、提供推荐 | 不能据此把多个候选降为唯一 |
| 系统自动补出的站点 | 展示当前建议 | 不能反过来作为证明当前建议的输入 |
| 未填写某站 | 不产生排除约束 | 明确删除必经站并要求换路的操作，才可形成局部排除意图 |

列车停站与物理经过站应分开。未在有乐町停靠不证明列车走地下线；明确输入有乐町站的人工经过记录，则要求所选路径包含该站成员。地理上从站附近驶过也不等于经过该站台。

## 用整段站序选择路径

在 `RailwayRouteChoices` 上增加独立的推断接口，不改变手动修正入口的用途。接口输入有序人工站点实例、已确认范围、车型、日期和可核验的服务线索；输出候选、排除理由、歧义范围以及搜索是否完整。

搜索状态包含当前物理线路或站台成员、已消费的人工站点出现序号、旅行方向和已确认区间位置。沿可通行的有向物理区间推进，在到达下一个人工站时消费一次出现实例。禁止只按站码合并不同站台，也禁止为每对相邻人工站独立选择最短路后拼接。

同名分段延续可复用现有连接规则。跨异名线路只使用有证据的连接关系；不能把步行换乘当成列车直通。缺少关系时保留缺口或要求用户分段，不凭附近轨道补边。

候选身份使用有序的区间编号和旅行方向。不能按站名列表、线路集合或几何重叠去重。用户明确记录 A→B→A 时，状态必须区别两次 A；避免无意义循环的限制不能删掉用户记录的回绕。

采用有上限的候选搜索，记录候选上限、展开次数和时间预算。只有搜索完整、当前数据覆盖充分且满足约束的物理路径恰好一条，才填为“根据已填信息匹配到的建议”。截断后即使只找到一条，也保留“还有路径未检查”的状态。最短路及分数领先只是推荐。

## 东京附近的判断示例

当前铁路包内有两类东京到品川的物理候选：地面东海道线行程依次经过东京、有乐町、新桥、浜松町、田町、高轮 Gateway、品川；总武地下候选为东京、新桥、品川。这是包内路径模型，不应等同于所有服务的停站表。

| 用户提供的信息 | 建议表现 |
| --- | --- |
| 东京→新桥→品川，均只知道车站名 | 按用户要求默认总武／横须贺，保留手动换为地面走向的入口 |
| 东京→有乐町站→新桥→品川 | 排除不包含有乐町站成员的地下候选；地面候选内部若仍有不同轨道，继续保留区别 |
| 东京→品川，没有填写有乐町 | 默认总武／横须贺，编辑器补出新桥及明确区间；这不证明地面路径不可能 |
| 已核验的成田特快班次，数据库有该班次具体物理区间 | 使用已关联区间；不得吸附到同为 JR 的地面轨道 |
| 用户手选总武地下走向，再修改无关区间 | 保留已有选择，只重算受影响范围 |

JR 东日本的[东京站构内图](https://www.jreast.co.jp/estation/stations/1039.html)分别列出地面在来线与地下总武站台；[新桥站构内图](https://www.jreast.co.jp/estation/stations/877.html)也区分地面与地下楼层。[有乐町站时刻表](https://timetables.jreast.co.jp/timetable/list1617.html)列出的运营系统为山手线和京浜东北线。这些资料支持站台与服务身份的区分，具体曲线仍须依据有来源的几何数据。

## 编辑器与保存

主页面按连续的物理选择显示区间摘要。共同路径自动保留；只在真正分岔的范围显示选择入口。候选说明应指出具体差异，例如“地下总武站台”和“地面在来线站台”，不只写“JR”。

每次消歧优先请求能最大程度拆分候选的一条线索：站台楼层、已知线路或车次。没有确定证据时允许保留未定草稿。无需为每一个自动补出的站点重复选线。

建议与手选的来源、确认状态和两端 `visitID` 分开持久化。保存时保留有向区间序列及重复出现，不用全程 `preferredLineNames` 集合替代。改站点使既有选择不兼容时报告受影响范围；改车次只重查依赖车次的建议。AI 应返回局部候选，应用时通过同一物理连通和确认锁检查。

建议最小实施顺序：先增加有序人工站序的候选过滤与歧义说明，再接编辑器的局部建议和持久确认，最后扩展有证据的跨异名线路搜索及 AI 局部补全。

## 验收条件

1. 东京→新桥→品川和东京→品川的无地面证据行程默认总武／横须贺；输入有乐町等人工站点，或明确手选地面线路，阻止默认改写。
2. 同站序但不同区间编号的候选不合并；同为 JR 不造成站台跳转。
3. 未填写、人工删除和系统补站分别处理，不以建议证明建议。
4. 正反方向、方向限制和 A→B→A 的重复出现保持正确。
5. 局部重算、保存重开、导出和 AI 不覆盖已手选区间。
6. 搜索截断不能宣布唯一；无证据的直通关系不能补成连接。
7. 新桥和赤羽桥分别检查网络、已乘路径及最终渲染。选对线路不表示曲线正确，显示修正也不应改写统计源坐标。
