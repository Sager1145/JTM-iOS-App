# JTM — Japan Train Map

[English](README.md) · **简体中文**

**记录铁路旅行，在地图上回顾行程，看看自己已经乘遍了多少线路。**

JTM 是面向 iPhone 和 iPad 的原生 SwiftUI 应用，也提供 Mac Catalyst 开发运行目标。它将行程记录、铁路地图、时刻表查询、旅行统计和分享整合在同一个工作区中，内置 **日本、台湾、香港、澳门和韩国** 五个地区的铁路网络。

行程库保存在你的设备上。基本的行程记录、路径计算、统计和 JSON 导入导出使用本地数据；Apple 地图和可选的 ChatGPT 功能需要使用在线服务。

[用户指南](docs/guides/user-guide.md) · [从源码构建](#从源码构建) · [开发文档](docs/README.md)

## 记录行程

选择地区、起点、终点和乘车日期，再填写列车类型、出发与到达时间，并将行程标记为已乘坐或计划乘坐。新建行程表单会查找两站之间的铁路路径，供你在保存前确认。

需要更详细的记录时，可以在行程编辑器中：

- 添加中途站、到发时间、站台和备注。
- 按区间记录运营商、线路、车次和列车名称，包括直通运行途中发生的变化。
- 指定途经站、根据本地铁路路径补齐站点，以及修正尚未解析的区间。
- 编辑、复制、调整顺序、在地图上隐藏或删除已保存的行程。

你可以浏览即将出发的行程、查看完整行程列表，或按行程、列车和车站信息搜索。规划未来旅行时，也可以先添加尚无行程的日期。日期筛选让列表和地图聚焦于所选时段，跨夜行程则保留各自的日界信息。

## 查询列车与补全信息

### 内置时刻表与停站模式

对于日本行程，可以根据行程中的列车信息搜索内置时刻表，也可以按日期、运营商和线路筛选停站模式。查看列车的停站信息及登记来源后，可用选定的时刻表或停站模式填充行程草稿，再继续编辑。

除了指定日期的结果，也可以浏览历史停站模式。覆盖范围取决于内置来源及其适用的运营日期；这是有来源依据的资料目录，并非实时发车看板，也不包含所有铁路的完整时刻表。

### 可选的 ChatGPT 辅助

输入列车名称、车次、路线和运营日期，查询相关资料；也可以将已发布的时刻表与其登记来源进行对照。查询结果与已保存的行程分开保留。

编辑器还提供 AI 补全，可建议缺失的列车信息、计划停站、站台，以及各区间的运营商、线路和车次。先检查建议和来源，再应用到草稿；已有的非空信息会保留。

你可以通过实验性的 ChatGPT 订阅集成使用账号提供的模型，也可以将补全提示词分享给 ChatGPT，再粘贴返回的 JSON。直接登录时，授权页面显示 **Codex**，可用性取决于账号。请求会将界面展示的行程上下文及你填写的查询备注发送给 OpenAI。

## 探索铁路地图

五个地区的铁路网络显示在同一个 Apple 地图工作区中。选择行程即可突出显示路线；点击重叠的乘车路径时，可以从候选行程中选择；打开车站卡片可查看名称、读音、运营商信息，并跳转到 Apple 地图。

- 显示或隐藏铁路线、车站、起终点、通过标记及不同类别的已乘路线。
- 调整路线与标记样式、选中效果，以及非所选日期行程的淡化程度。
- 查看当前铁路网络、所选行程日期的网络，或内置历史数据所支持的历史叠加层。
- 定位当前位置、缩放至整个网络或所选内容、调整缩放并重置指南针。
- 选择完整显示跨夜行程，或区分属于另一天的部分。

路径计算依据内置的铁路物理拓扑。站台相邻、站名相同、允许换乘或存在直通列车，都不能单独证明轨道相连。如果现有证据无法解析某段行程，路径可以保持待确认状态，其精确里程也可能不完整。

## 查看旅行统计

统计工作区汇总已乘坐的行程，提供：

- 行程数、乘车天数、停站数和乘车总时长。
- 按铁路或列车类别划分的里程。
- 铁路网络覆盖率及各线路明细。
- 按次数或距离排列的车站、运营商、路线和常乘区间排名。
- 按年份、月份和星期统计的乘车分布。
- 所选日期的距离与时长。

可以查看单个地区或全部地区，日本还提供更细的区域选项。里程和覆盖率取决于行程的路径解析结果，以及相应统计范围使用的内置铁路网络。

## 回放与分享

在地图上回放行程，支持暂停与继续、速度调整、上一段与下一段行程、可选的聚焦缩放、已行驶路径轨迹，以及结束时的全程概览。回放还可以导出为视频，并设置画面比例、质量和码率。

你可以将单段行程分享为图片，也可以使用分享编辑器，在画布上组合行程、地图和统计卡片。移动卡片、调整大小、选择日期和地区范围、切换外观，并导出正方形、横向或纵向图片，包括 16:9 和 9:16 比例。

## 导入、备份与带走记录

数据资料库集中管理导入、导出、示例和恢复操作：

| 操作 | 支持的流程 |
| --- | --- |
| 导入 JSON | 打开文件或粘贴规范格式的完整数据、列车数组或单个列车对象；检查校验结果后，追加到现有行程库或替换整个库。 |
| 导入截图 | 使用设备端 Vision OCR 识别受支持的日本换乘查询截图；保存前检查解析出的各段行程、车站匹配、时间、站台和票价。 |
| 体验示例行程 | 加载内置地区示例和特别行程，再作为自己的记录继续编辑。 |
| 导出记录 | 保存或复制使用 `schema_version` 和 `trains` 字段的规范 JSON。 |
| 恢复行程库 | 恢复在受支持的破坏性操作前创建的恢复备份。 |

行程以本地 JSON 存储，通过串行、原子写入保存。应用状态目录不参与 iCloud 备份；需要可携带的记录副本时，请导出 JSON。

## 语言与设备支持

界面支持 **繁体中文、简体中文、日语和英语**。车站名称使用各地区的数据，并在数据可用时提供可选的假名、罗马字和中文读音。行程翻译可以独立于界面语言开启。

iPhone 使用竖屏；iPad 支持横屏和竖屏。应用目前将动态字体大小限制在 `.xSmall ... .xLarge` 范围内。

## 从源码构建

### 环境要求

- 安装了 Xcode 的 macOS。文档记录的开发工具链为 **Xcode 27.0 beta、Swift 6.4 和 iOS 27 SDK**，应用最低部署版本为 **iOS 17.0**。工具链详情见 [iOS 工程说明](ios/README.md)。
- Git LFS，用于获取 `app/data/rail.db`；该派生数据库供铁路网络查询和交叉核对使用。
- 仅在修改 JavaScript 参考实现、测试夹具或数据构建器时，需要 `.node-version` 指定的 Node.js **26.4.0**。

在已有的仓库检出目录中执行：

```sh
git lfs install
git lfs pull
open ios/JTM.xcworkspace
```

选择 **RailMap** scheme，再选择 iPhone 或 iPad 模拟器运行。使用真机时，请配置开发团队签名。在 Mac 上开发时，选择 **My Mac (Mac Catalyst)**。也可以直接打开 `ios/RailMap.xcodeproj`，仅开发主应用。

应用使用仓库中已构建的铁路包和运行时资源。原始 GIS 下载及来源研究输入仅保存在本地，运行内置应用不需要这些文件。重新构建相关产物时，需要准备对应的留存输入，详情见 [铁路源数据中心](railway-sources/README.md)。

### 诊断工具

工作区还包含三个独立的 Mac Catalyst 工具：

| Scheme | 用途 |
| --- | --- |
| `RouteWorkbench` | 检查物理路径求解和已保存的行程证据。 |
| `ThroughWorkbench` | 审查历史直通服务的有效期及补丁。 |
| `RailAlignmentInspector` | 将显示几何与原生底图快照进行对照。 |

项目位置和使用方式见 [诊断工具说明](ios/auxiliary/README.md)。

## 仓库结构

原生应用负责 SwiftUI、MapKit、Vision OCR、回放与视频编码、持久化和账号集成。本地 Swift 包将可复用逻辑划分为三个模块：

| 模块 | 职责 |
| --- | --- |
| `RailCore` | 行程模型、校验、日期、路径计算、几何、时刻表访问、导入、统计和序列化。使用 Foundation，SQLite3 仅用于只读时刻表访问。 |
| `RailApplication` | 基于快照处理导入暂存、草稿校验和路径／里程用例；依赖 Core。 |
| `RailPresentation` | 搜索与显示策略、交互决策、时钟和地图链接；依赖 Core，与 Application 相互独立。 |

`app/` 保留 JavaScript 参考行为和铁路数据构建器。已提交的 `port-fixtures/` 记录 Swift 与 JavaScript 共享逻辑的预期结果。

```text
ios/
  RailMap/              原生应用及功能界面
  RailKit/              Core、Application、Presentation 和包测试
  RailMapTests/         应用回归测试
  RailMapUITests/       原生 UI 回归测试
  auxiliary/            诊断工具
  JTM.xcworkspace       主应用与诊断工具的工作区
app/
  data/                 已构建数据库、车站表和示例行程
  public/rail/          已构建铁路包及来源归属说明
  scripts/              保留的数据构建器和辅助工具
port-fixtures/          共享行为测试夹具
docs/                   指南、参考、决策和带日期的证据
railway-sources/        来源目录；原始输入仅保存在本地
```

### 开发与验证

先审查修改的代码或数据及其受影响的依赖。共享行为需要对照相关 Swift 和 JavaScript 实现；铁路身份变更需要检查对应的内置引用。只有在需要解决具体正确性问题时，才运行针对性的现有测试、数据查询或增量构建。

按需使用的 `ios/verify.sh` 提供独立的 `swift`、`build`、`route` 和 `alignment` 模块，不带参数运行时显示帮助，不会启动自动全量验证流水线。请遵循 [当前验证政策](ios/VERIFICATION.md)，复用仍然适用的证据，并协调同一时间只运行一个重型任务。

本文介绍代码中已实现的功能界面。当前验收问题和带日期的结果保留在 [工作范围记录](ios/refactor-parallel/) 和 [报告](docs/reports/) 中。
