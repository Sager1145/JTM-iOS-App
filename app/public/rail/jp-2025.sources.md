# Japan rail package 2025 — rebuilt

`jp-2025.json`, format **`compact-v1`**, version **2025.5.0**. Geometry is
N02-derived except for registered physical-track corrections on the Tokyo-adjacent
intervals of both Shinkansen, the shared 東北・東海道 surface stroke, and the
総武快速・横須賀線 東京トンネル; OSM-derived attributes and colour provenance
are kept separate.

Current characterized package: **657 display lines / 9,569 intervals / 10,223
display-station rows / 9,039 physical station groups**. The whole-country
multi-line audit covers 1,266 candidate groups, including all 880 groups on two
or more display lines and every station touched by a final lane profile.

## Pipeline

```
N02-25 geometry + stations
  └─ build-japan-package-from-inventory.py evidence-driven station intervals
  └─ promote-lines.mjs --all --prune     full staging promotion; remove stale strokes
  └─ split-interleaved-branches.mjs      trunk/branch station topology
  └─ repair-doubling-back-intervals.mjs  verified false lead-in folds
  └─ restore-n02-loop-line-geometry.py   repeat-coordinate spiral loops
  └─ build-parallel-corridors.mjs        global stable screen-space lanes
  └─ finalize-japan-package.mjs          provenance, structure bounds, gzip
  └─ audit-japan-multiline-stations.mjs  A–E source/render junction audit
```

Rebuild:

```bash
npm run rebuild:railway:jp
npm run audit:apple-tiles:jp
node scripts/validation/audit-japan-multiline-stations.mjs --strict
```

## Official sources

- **国土交通省 国土数値情報 鉄道データ N02-25**（基準年月日 2025-12-31）
  <https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-N02-2025.html>
  Geometry, line name, operator, railway class, station name / code / group code.
  出典「国土数値情報（鉄道データ N02）」（国土交通省）を加工して作成。
  **Read the `Shift-JIS/*.shp` copy** — the UTF-8 shapefile is rounded to 8 dp
  (448 sections differ) and its DBF carries LDID 0x00 with no `.cpg`, so a
  default read mojibakes.

- **OpenStreetMap contributors**, Geofabrik `japan-latest.osm.pbf`,
  data timestamp 2026-08-11T20:22:05Z, **ODbL 1.0**.
  English/kana station names, tunnel/bridge intervals, and a colour fallback.
  Kept in their own tables with per-row provenance. Registered geometry
  corrections replace N02-25's coarse Tokyo-adjacent chords with the selected
  physical OSM rails: JR Central's eastern 東海道新幹線 track, JR East's
  20-23-side 東北新幹線 track, one Sapporo-style welded junction and shared
  render lane for the continuous 東北線—東海道線 surface track, and the west
  bore of the 総武快速・横須賀線 東京トンネル
  in both directions. Exact source ways, replacement coordinates and fail-closed
  N02/platform matches are recorded in
  `data/raw/railway/jp/evidence/tokyo-station-platforms.json`.

- **Multi-line station evidence and classifications** — automatic A–E rules,
  source priority, junction election and explicit Tokyo/Sapporo decisions are
  recorded in `data/raw/railway/jp/evidence/multi-line-station-audit-rules.json`.
  Full CSV/JSON/Markdown results are generated under
  `outputs/railway-audit/multi-line-stations/`. Apple rows that have only been
  inventoried remain `pending_dedicated_capture`; the report never promotes a
  queued image to a completed visual sign-off.

- **Line and operator colours** — see `colours/sources.md`. Tokyo Metro, Osaka
  Metro and Nagoya are official published values; the JR corporate colours are
  the de-facto values parsed out of the Commons `JR_logo_(*).svg` `fill:`
  attributes and are marked `medium` confidence. ODPT is **not** used: its
  Basic Licence Art.8(4)(1) forbids redistributing derived data.

## Enriched `compact-v1` fields

| field | meaning |
| --- | --- |
| `lines[].kind` | `shinkansen` / `jr_conventional` / `subway` / `private` / `third_sector` / `tram` / `monorail` / `agt` / `funicular` / `maglev` |
| `lines[].colorPolicy` | `line` or `operator` |
| `lines[].colorDark` | lightened for a near-black surface, hue preserved |
| `lines[].lineCode` | line letter where the operator publishes one |
| `lines[].structure` | line-global `[fromM, toM, 1=tunnel/2=bridge, layer]`; branch splitting remaps these measures |
| `lanes[]` | `[lineId, partIndex, fromM, toM, signedLane]`; independent railways only |
| `lines[].railwayIdentity` | persisted physical-railway identity shared by canonical siblings and explicit cross-canonical continuations |
| `attributeSources` | separate provenance for OSM names/structure and the colour tables |

## The two invariants

1. **Parallel geometry and line weight share one zoom scale.** Lane offset,
   gap, casing, line width and station dots all use `railwayScale()`. Their
   scale-normalized proportions are stable across z3–z18.

2. **A pair never swaps sides.** Lane order is decided once over the complete
   corridor graph; each local member set reads a subsequence of that order,
   and anti-parallel digitisation is corrected before `line-offset` is stored.

3. **A junction survives final lane rendering.** A two-stroke continuation
   carries one screen-side lane through its exact node; a true branch ramps all
   arms back to lane 0 at the station. Thus a lane offset cannot split one
   physical junction into several visible station points.

`railway-parallel-corridors.test.js`, `station-render-anchoring.test.js`,
`japan-rail-continuity.test.js` and the strict validators assert these
contracts against the final package.

- **2026-09-04** — `jp-西日本旅客鉄道-東海道線-2` (梅田貨物線, 大阪 → 福島)
  segment 0 declared `0.698` km while its own shipped geometry (12-vertex
  polyline, both endpoints on their station anchors) walks `0.873` km by
  standard haversine summation — a `LENGTH_DISAGREES` preflight error. The

  passenger-timetable distance, so geometry is the best available reference.

  `0.873` (haversine-measured, rounded to 3 dp). jp has no stored line-level
  `lengthKm`; the WebUI/database loader (`app/scripts/build/rail-database/load.mjs`)
  derives it at load time as the sum of segment km rows, so it now reflects
  the corrected figure automatically. **Not corrected**: the line's
  `structure` array still ends its last (bridge) entry at `698`, i.e. it is
  now ~175 m short of the corrected 873 m interval — flagged for the next
  builder regeneration, left alone here as out of this edit's scope.
