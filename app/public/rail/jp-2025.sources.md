# Japan rail package 2025 — rebuilt

`jp-2025.json`, format **`compact-v1`**, version **2025.5.2**. Geometry is
N02-derived except for registered physical-track corrections on the Tokyo-adjacent
intervals of both Shinkansen, the shared 東北・東海道 surface stroke, and the
総武快速・横須賀線 東京トンネル; OSM-derived attributes and colour provenance
are kept separate.

Current compact package: **657 line rows / 9,578 intervals / 10,231
station rows / 9,041 station codes**. The original whole-country
multi-line audit covered 1,266 candidate groups, including all 880 groups on two
or more display lines and every station touched by a final lane profile.

## Pipeline

### Tokyo tunnel restoration and legacy southern branch integration (2026-10-01)

The current requested map convention restores the Sobu/Yokosuka tunnel through
Shimbashi and joins the conventional display family at Shinagawa. It supersedes
the earlier south-of-Yurakucho schematic. The retained Tokyo tunnel survey is
used up to the Shinagawa throat; an explicitly display-only smoothstep endpoint
alias over the last 350 m reaches the existing conventional station anchor.
Shimbashi uses its original tunnel seam vertex (1.5 m from the N02 anchor) to
avoid a station barb, and retains a distinct underground circle. The outbound
display reuses the old N02 approach and both existing branch boundaries at
`[139.73762,35.62049]` and `[139.7328,35.61677]`.
Original compact stations, physical intervals and mileage remain authoritative
for routing and statistics. This convention is not a physical track connection.
Replay the package with
`repair-tokyo-platform-approaches.py`, then rebuild display lanes and the native
display derivative.

Two independently surveyed 大崎支線 alignments supplement the missing
大崎–西大井 physical edge. Geometry is from the retained 2026-08-18
OpenStreetMap cache, WGS84, © OpenStreetMap contributors / ODbL 1.0;
`tokyo-southern-branches-overrides.json` contains the exact ordered way IDs,
coordinates and independently sourced JRTT topology evidence. Their
Original station-free fork approaches remain in `southernBranchTopology`.
Display aliases project the forks onto the old N02 representative within 15 m;
the displayed north lead-ins and southern tails reuse that existing geometry.
The extra parallel freight-main display is removed. The old `alignmentPairs`
declaration accompanies the paired row without inventing railway up/down.
Station properties follow ADR 0010 with the existing `display_line_id` field;
provenance stays in the evidence registry and feature foreign member rather
than introducing incompatible station properties. No passenger stop is added.
See [the current repair report](../../../docs/tokyo-osaki-legacy-repair-2026-10-01.md)
and [the source branch audit](../../../docs/tokyo-southern-branch-audit-2026-10-01.md)

### Bounded Tokyo override (2026-09-30)

`python3 app/scripts/railway/repair-tokyo-platform-approaches.py` replays the
override in this checkout; `--check` verifies it. The original Japan inventory
builder and raw 2026-08-18 OSM evidence remain in the older Web repository.
This repair removes only the two reversed seam vertices immediately north of
the Shinagawa Tokaido Shinkansen anchor; it keeps both interval endpoints and
every subsequent surveyed vertex, and recalculates that interval's haversine
length. It adds no new survey or source licence (N02 / ODbL attribution above).

At the main JR Tokyo complex (`003766`), the display circles represent four
platform families: Sobu/Yokosuka, conventional surface, northern Shinkansen,
and Tokaido Shinkansen. `stationCircleOwnerByCode` keeps duplicated members
available to routing and interchange details while electing one visual circle;
`stationLaneByCode` seats both approaches on their family's circle. The remote
Keiyo platforms (`003785`) and Metro platforms remain separate. This is an
explicit display policy, not a claim that the physical station has four islands.
JR East's [Tokyo station plan](https://www.jreast.co.jp/estation/stations/1039.html)
and [N'EX route](https://www.jreast.co.jp/train/express/nex.html), checked
2026-09-30, distinguish the Sobu/Yokosuka underground corridor from the surface
railways. Coordinates stay WGS84.

## Enriched `compact-v1` fields

| field | meaning |
| --- | --- |
| `lines[].kind` | `shinkansen` / `jr_conventional` / `subway` / `private` / `third_sector` / `tram` / `monorail` / `agt` / `funicular` / `maglev` |
| `lines[].colorPolicy` | `line` or `operator` |
| `lines[].colorDark` | lightened for a near-black surface, hue preserved |
| `lines[].lineCode` | line letter where the operator publishes one |
| `lines[].structure` | line-global `[fromM, toM, 1=tunnel/2=bridge, layer]`; branch splitting remaps these measures |
| `lanes[]` | `[lineId, partIndex, fromM, toM, signedLane]`; independent railways only |
| `lines[].railwayIdentity` | persisted physical-railway identity shared by canonical siblings and explicit cross-canonical continuations |
| `attributeSources` | separate provenance for OSM names/structure and the colour tables |

## The two invariants

1. **Parallel geometry and line weight share one zoom scale.** Lane offset,
   gap, casing, line width and station dots all use `railwayScale()`. Their
   scale-normalized proportions are stable across z3–z18.

2. **A pair never swaps sides.** Lane order is decided once over the complete
   corridor graph; each local member set reads a subsequence of that order,
   and anti-parallel digitisation is corrected before `line-offset` is stored.

3. **A junction survives final lane rendering.** A two-stroke continuation
   carries one screen-side lane through its exact node; a true branch ramps all
   arms back to lane 0 at the station. Thus a lane offset cannot split one
   physical junction into several visible station points.

`railway-parallel-corridors.test.js`, `station-render-anchoring.test.js`,
`japan-rail-continuity.test.js` and the strict validators assert these
contracts against the final package.
