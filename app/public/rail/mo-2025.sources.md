# Macao LRT package 2025

`mo-2025.json` contains every currently operating Macao LRT line: Taipa Line,
Seac Pai Van Line and Hengqin Line. The East Line is under construction and is
therefore not shown as an operating railway.

## Identifier conventions (2025.2.0)

- Display line ids follow the Japan/Taiwan convention: `mo-mlm-taipa`,
  `mo-mlm-spv`, `mo-mlm-hengqin`.
- Station group ids share the solver-dataset spelling `mo-official-…`.
- Station CODES (`n02_station_code`, e.g. `MLM-TAIPA-MLM-BARRA`) are persisted
  identifiers and keep the pre-normalization spelling; the readings table also
  resolves network aliases `{lineId}:{stationGroupId}`.
- `country` is uppercase `MO`, `crs` is `WGS84`, and `geometrySource` carries
  `providers` / `license` / `sourceSha256` provenance like `tw-2025.json`.

## Rebuild

`$MO_SCRATCH` is any writable directory chosen by whoever runs the build; the
three DSCC responses are not committed. See **Unresolved provenance** below
before treating those file names as a source.

```bash
# 1. Route centre-lines from DSCC's Online Map responses (needs pyproj):
python3 scripts/railway/build-macao-track-alignments.py \
  --taipa "$MO_SCRATCH/mo-dscc-taipa.json" \
  --seac-pai-van "$MO_SCRATCH/mo-dscc-spv.json" \
  --hengqin "$MO_SCRATCH/mo-dscc-hengqin.json" \
  --output data/raw/railway/mo/mo-track-alignments.json

# 2. Package + solver datasets + readings + sample store:
python3 scripts/railway/build-macao-rail-package.py

# 3. Precomputed sample parts:
npm run precompute:mo
```

## Official source

- Macao Light Rapid Transit Corporation, official LRT Lines page: current
  lines, transfer relationships and station order:
  <https://www.mlm.com.mo/en/route.html>
- Operator station-location pages linked from that route page: station map
  anchors and English names.
- Cartography and Cadastre Bureau (DSCC), Macao Online Map LRT route planner:
  <https://webmap.gis.gov.mo>
- DSCC mapping-service catalogue: <https://www.dscc.gov.mo/en/services_system.html>

### Unresolved provenance — the three DSCC route responses

The publisher of the route geometry is recorded above, but the *request* that
returns it is not: no service endpoint, no layer or query parameters, no fetch
date, and no fingerprint of the responses themselves — the package's
`geometrySource.sourceSha256` covers only the derived
`mo-track-alignments.json`. `mo-dscc-taipa.json`, `mo-dscc-spv.json` and
`mo-dscc-hengqin.json` were previously cited by their scratch paths, which
recorded nothing durable, and the script that fetched them is no longer in
this tree.

The geometry of all three Macao lines rests on those responses, so a
questionable segment cannot currently be traced past "DSCC Online Map" to a
re-fetchable source. Recording the DSCC service URL and parameters for each
line is open work; no URL is asserted here in the meantime, because a guessed
endpoint would be a worse record than an acknowledged gap.

## Geometry method

The package uses the route polyline and station markers returned by DSCC's
official Online Map for LRT routing. Coordinates are converted from Macao Grid
(EPSG:8433) to WGS84, simplified at two-metre tolerance, and split at each
station's projected position. The former hand-traced station coordinates and
straight station-to-station connectors are no longer used. This remains
cartographic route geometry rather than an engineering survey.
